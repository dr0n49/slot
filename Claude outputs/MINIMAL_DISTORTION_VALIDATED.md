## 1. Алгоритм

Изолированный модуль `games/nitro_vein/uniform_tilt.py`. Штатный оптимизатор не тронут и
продолжает работать.

**Шаг 1 — вероятности критериев берутся из самой игры.**

```
P(freegame) = 1 / 181.0   = 0.55249 %     натуральная частота фичи
P(zero)     = 37.730 %                    натуральная доля нулевых раундов
P(basegame) = 1 - P(freegame) - P(zero) = 61.7175 %
```

Обе величины измерены на production-коде в честном режиме, 800 млн раундов. Книга критерия
`basegame`, которая заплатила ноль, относится к нулевой группе — «basegame» значит
«базовый раунд, который заплатил».

**Шаг 2 — внутри критерия все книги равны.**

```
p(book) = P(criterion) / (число книг этого критерия)
```

Ничто не отличает одну книгу от другой: форма, которую породила симуляция внутри критерия,
сохраняется целиком.

**Шаг 3 — один глобальный монотонный наклон под RTP.**

```
q(book) ∝ p(book) · exp( −λ · win(book) )
```

Одна λ на всю библиотеку. Без диапазонов выплат, без коэффициентов по критериям, без
`distribution_bias`. Среди всех перевесовок, удовлетворяющих ограничению по RTP, эта имеет
минимальную KL-дивергенцию от равномерной конструкции — то есть она доказуемо наименее
искажающая из перевесовок такого вида.

**Шаг 4 — целочисленные веса** формата lookup-таблицы, отмасштабированные так, чтобы
максимум был 10¹⁰ и ни один не округлился в ноль.

### Какой наклон потребовался

| Режим | RTP до наклона | **λ** | RTP после | Разброс весов |
|---|---:|---:|---:|---:|
| base | 96.2454 % | **0.00001974** | **96.0000 %** | 37.29× |
| bonus | 97.3917 % (95.931× за фичу) | **0.00011492** | **96.0000 %** (94.560×) | 1.18× |

λ базового режима — 2·10⁻⁵: на выигрыше ×100 множитель веса 0.998, на ×1000 — 0.980.
Наклон почти не ощутим, что и требовалось.

37.7 % массы, фича-книг 20 тыс. на 0.55 %), а не перераспределение внутри.
