Состояние проекта на конец W4 / перед MATH FREEZE.

## 1. Стек (важно помнить)

Не Godot. Фронт — **SvelteKit + Svelte 5 runes + PixiJS 8**, `work/web-sdk/apps/nitro-vein`.
Математика — **Python/Rust math-sdk**, `work/math-sdk/games/nitro_vein`. Связь через
RGS-книги Stake Engine. Отдельная песочница анализа — `work/mathlab` (в игру не входит).

Игра: каскадный ways-слот **5 барабанов × 6 рядов = 30 позиций**, платят 4 и 5 в ряд,
механика-идентичность — Blast Ladder.

## 2. Зафиксированная математика (модель B + K-4)

| Параметр | Значение |
|---|---|
| Base ladder | `[1, 2, 3, 5, 10, 20, 50]` |
| Free ladder | `[2, 4, 8, 16, 35, 80, 200]` |
| Правило кегов | **K-4**: шаг проходит ступени `i … min(i+k, top)` и **платит на каждой пройденной ровно один раз**; следующий каскад с `min(i+k+1, top)` |
| Сброс лестницы | каждый спин, в базе и во фриспинах одинаково |
| WINCAP | 3000× |
| BONUS_COST | 98.5× |
| PAYTABLE | готовые значения, без `PAYTABLE_SCALE` |
| Квантование выплат | 0.01×, без пола |
| Скаттеры | точные количества по лентам `[3, 0, 2, 0, 2]` — только барабаны 1 / 3 / 5 |
| Фриспины | 3 скаттера → 10 FS; ретриггер 3 скаттера → +5 FS |
| Породы `R` | 22 (base) / 10 (free) |
| Кег `K` | 3 / 5, вайлд `W` | 3 / 5 (вайлда нет на барабане 1) |
| Критерий `wincap`, ленты `FRWCAP` | удалены полностью |

PAYTABLE (выплата за одну way):

| | H1 | H2 | H3 | H4 | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|---|---|---|---|
| 4 в ряд | 0.1125 | 0.0850 | 0.0560 | 0.0420 | 0.0200 | 0.0155 | 0.0125 | 0.0100 | 0.0085 |
| 5 в ряд | 0.3500 | 0.2800 | 0.1830 | 0.1270 | 0.0560 | 0.0450 | 0.0350 | 0.0280 | 0.0225 |

Цели оптимизатора: `rtp_share = {freegame 0.535, "0" 0.0, basegame остаток 0.425}`,
`hit_rate = {freegame 180, basegame 1.621}`. **Все ручные constraints убраны** —
`ConstructScaling` пустой в обоих режимах, `distribution_bias` удалён.

## 4. Пройденные волны

**W1 — аудит.** Главная находка: старую игру ломал не дизайн, а оптимизатор. Натуральный
RTP был 137.7 %, фича 1 / 48; опубликованная сборка 96 % и 1 / 186. Лестница в базе была
мертва (81 % раундов на ×1), ступень ×50 недостижима, максимум 10 000× сконструирован на
служебной ленте.

**W2 — архитектура фронта.** Новые `roundResult.ts` (результат раунда читается из книги до
первого кадра) и `roundContext.ts` (состояние презентации на раунд). Убрано модульное
состояние `stepIndex` / `spinBase` / `pendingLines`. Двухступенчатый watchdog: 90 с —
перемотка, 120 с — закрытие раунда из известного результата. Recovery восстанавливается из
результата книги.

**W3 — новая математика.** Всё из §2. K-4 доказан юнит-тестами на реальном `GameState`,
включая полный перебор «ступень × 0…30 кегов» на обеих лестницах. События книги несут полный
список пройденных ступеней (`ladder.rungs`, `kegBlast.rungs`) — презентация ничего не считает.

**W4 — Monte Carlo с оптимизатором.** Три итерации:

## 6. Открытые вопросы

**Кап 3000×.** В опубликованной библиотеке из 200 тыс. книг всего 14 книг выше ×1000, одна
выше ×1500, максимум 1 563×, выше ×2000 — ноль. Лаборатория на 100 млн видела 2 465×.
То есть отсутствие 3000× сейчас — следствие размера выборки, а не доказательство
невозможности. Ответ даст `cap_probe` плюс финальный большой прогон.

**Финальный прогон.** Согласовано 5 млн базовых книг для статистики хвоста. По времени —
порядка трёх часов генерации; оптимизация на таком объёме отдельно по памяти и времени.

**Хвост и размер библиотеки.** Цель `P(≥×1000) = 1 / 295 000`. На 200 тыс. книг разрешения
по этому хвосту физически нет.

## 8. Ограничения окружения, о которых стоит помнить

* Генератор книг падает по памяти на больших батчах bonus-режима (worker убивался на 5.3 ГБ,
  родительский процесс молча висел). Рабочий режим — `--threads 1 --batch 2500` для bonus.
* Rust-оптимизатор один раз упал на `--threads 2`; на одном потоке стабилен.
* `export_frontend.py` и пара файлов SDK требуют Python 3.12 (f-strings с вложенными
  кавычками); в контейнере по умолчанию 3.11.
* Репозитории `web-sdk` и `math-sdk` — клоны StakeEngine, прав на пуш нет. Все изменения
  локальные и незакоммиченные. Сборка проекта для тебя лежала в `~/slot/slot2-bundle/`
  (git-бандл), с тех пор накопились W2 / W3 / W4 — бандл не пересобирался.
