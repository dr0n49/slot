## 1. Аудит текущего flow (перед правками)

Просканировано 120 000 production-книг. Частоты событий на книгу:

| Событие | На книгу |
|---|---:|
| `updateLadder` | 3.06 |
| `winInfo` | 1.90 |
| `kegBlast` | 0.98 |
| `freeSpinTrigger` | 0.101 |
| `freeSpinRetrigger` | 0.010 |

58.89 % раундов — это `reveal → setTotalWin → finalWin`, то есть вообще без выигрыша.

**Главная находка аудита.** `winInfo.ladder.rungs` уже содержал выигрыш каждой ступени
(`{index, multiplier, win}`), но презентация его игнорировала: лестница прыгала сразу на
суммарный множитель. Реальный пример из книги 12: `rungs [{0,×1,2},{1,×2,4},{2,×3,6}]`,
итог `×6`, переход `0 → 2`, следующая ступень 3. Игрок видел «×6» и не видел, из чего он
сложился.

## 2. K-4 presentation

Добавлен чистый планировщик `presentationPlan.ts`. Он **ничего не вычисляет**: берёт список
ступеней из `kegBlast.rungs`, сопоставляет с `winInfo.ladder.rungs` по индексу и возвращает
порядок показа. Суммарный множитель берётся из события (`blast.multiplier`), а не складывается
заново — на это есть отдельный тест с намеренно противоречивым событием.

Теперь взрыв кега проходит **каждую ступень отдельным состоянием на экране**: ступень
подсвечивается, рядом появляется её собственный вклад (`+0.30`), звук тика повышается по
высоте, и только после прохода всей лестницы показывается сумма. Ни одна ступень не может быть
пропущена — их порядок задаёт книга.

Скриншот `cat-massive.png`: подъём подсвечен от ×2 до ×35, ходьба заканчивается на верхней
ступени ×200 с бейджем вклада `+7.01`, снизу `NEXT WIN ×200` и `TNT +2`.

## 3. Темп каскадов

`planStep` даёт обычному шагу короткую паузу, а заметному — больше воздуха. Эмфаза растёт от
двух независимых источников: размера выигрыша (≥1× и ≥10× ставки) и высоты ступени (от 3-й и
выше). Оба значения приходят из события.

## 4. Feature progression

Правила заморожены, поэтому презентация только сопровождает их: 3 скаттера → 10 фриспинов,
ретриггер +5. Баннер входа теперь формируется через `triggerText()`, который **называет число
скаттеров только если оно равно 3**; для любого другого значения выводится «SCATTERS» без
числа. Это защита в глубину — таких книг нет, но баннер не должен рекламировать вход, которого
в игре не существует. Количество спинов печатается из книги как есть.

Аутро фичи держится дольше, если выигрыш заслужил празднование (`featureOutroHold`).

**Проверено в браузере поэлементно** (не по плоскому тексту, чтобы соседние элементы не
склеивались): за все прогоны на экране встречается только `3 SCATTERS`, счётчик всегда `n/10`.
Нарушений — 0.

## 5. Найденные и исправленные дефекты

Три настоящих бага, найденных браузерным прогоном, а не предположением.

**5.1. Падение презентации на уничтоженном спрайте.** `PAGEERROR: Cannot read properties of
null (reading 'x')`. PixiJS обнуляет трансформ при `destroy`, а анимация падения символа
продолжала писать `v.y`. Исключение вылетало из цикла планировщика и **обрывало все остальные
задачи кадра** — их промисы не разрешались никогда, раунд вставал до срабатывания watchdog.

Исправлено в трёх местах: охранные проверки в обеих анимациях падения (`board.ts`), проверка
живости цели в `tween`, и — главное — `try/catch` вокруг шага задачи в планировщике, чтобы
одна сломанная анимация не роняла остальные.

**5.2. Зависший continue-gate.** Гейт ожидания игрока мог пережить свой раунд. Теперь он
снимается при skip, при принудительном завершении и при восстановлении, а новый гейт сначала
освобождает предыдущий вместо наложения.

**5.3. Темп длинного раунда (главное).** Модель бюджета показала, что при неактивном игроке
**14.5 % раундов превышали порог fast-forward (90 с), а 2.3 % — порог принудительного
завершения (120 с)**. То есть watchdog регулярно срабатывал на совершенно здоровых раундах.
Худшая книга — 317 событий, ~211 с.

Добавлен `tempo()`: первые 15 с раунда играются в полную силу, дальше паузы плавно сжимаются
до 30 %. Результат по всем 7 878 книгам:

| Метрика | Было | Стало |
|---|---:|---:|
| Худший раунд | 211.3 с | **81.3 с** |
| Книг свыше 90 с | 1 143 (14.5 %) | **0** |
| Медиана раунда | 11.7 с | **11.7 с** |
| Раундов без изменений | — | **50.4 %** |

Медиана не изменилась: сжимается только длинный хвост. Пороги watchdog оставлены прежними
(90 с / 120 с) — я их поднимал, но откатил, потому что поднимать порог под плохое измерение
неправильно; чинить надо было темп.

## 6. Архитектура раунда сохранена

`roundResult` по-прежнему читается из книги до первого нарисованного кадра и остаётся
авторитетным. `settleToResult` и `recoverFromError` приводят экран ровно к нему. Ни один
обработчик не вычисляет выигрыш.
