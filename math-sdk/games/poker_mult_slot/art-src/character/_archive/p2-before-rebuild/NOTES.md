## Иллюстрация и свет

Сахарный череп, широкий капюшон, высокий воротник дилера, вышитый жилет, бархатцы и колода
связывают героя с нашим золотым Reaper joker. Разворот 3/4 направлен вправо, к полю.
Контуры тёмные, поверхности разбиты на крупные цветовые плоскости с cel shading.
BASE: слоновая кость, чёрный, красный/oxblood, золото; свет сверху слева.
FS: холодная кость, deep blue, violet, cyan по левому краю; золото и бархатцы остаются тёплыми.

Основные FS-панели отдельно перекрашены через ImageGen. Скрытые участки, кисти и часть мелких
деталей получают палитру из нашего FS-этюда; альфа берётся из BASE. Геометрия обоих skins одна.
Исходные рисунки имеют разные нативные размеры, перечисленные в `qa/artwork-check.json`.
2800 px — размер собранного экспорта из отдельных источников с регистрацией и ресэмплингом,
а не заявление о едином нативном рисунке 2800 px. Оригиналы сохранены.

Для desktop ориентир — около **940 px видимой высоты** (87% от 1080): итоговый масштаб примерно
0,34. Размещение в игре не входит в P2. Силуэт нужно вписать в левую колонку, сохранив поле и HUD.

## Детали и порядок рисования

Мягкие непрерывные панели, уже экспортированные как weighted meshes:

- `cape` — цельная передняя панель плаща с завершённым нижним силуэтом и закрытой спиной/шеей под жилетом.
- `hood_back` — отдельная внутренняя/задняя обёртка; заполнена тканью за черепом.
- `face_neck` — целый череп, челюсть, шея и ключицы; верх головы дорисован под капюшоном.
- `left_sleeve`, `right_sleeve` — цельные рукава от плеча до манжеты, включая скрытые заходы под корпус.
- `hood_front` — одна панель от макушки до плеч; отверстие для лица прозрачно, края целые.
- `ribbon_left`, `ribbon_right` — две цельные ленты с костями у крепления и кончика.

Жёсткие детали и накладки:

- `chest` — полный жилет с высоким воротником; region на кости chest.
- `left_wrist`, `right_wrist` — точные накладки манжет из соответствующих рукавов.
- `marigold_leaves`, `marigold` — листья и цветок; крепятся к цепочке garland.
- `deck` — целая колода, включая поверхность и края за пальцами.
- `left_eye`, `right_eye` — отдельные внутренние области глазниц.
- `left_eye_glow`, `right_eye_glow` — отдельные янтарные/cyan огни, additive, выключены в setup.

Кисти — region attachments на соответствующих hand slots:

- `left_hand_idle`, `left_hand_card`, `left_hand_point`, `left_hand_open`.
- `right_hand_idle`, `right_hand_card`, `right_hand_point`, `right_hand_open`, `right_hand_deck`.

Итого **27 PNG на skin**, без групп и фонового слоя. Имена совпадают с костями или с attachment
своего hand slot. Root, IK targets и вспомогательные pivots не имеют PNG, потому что это управляющие
кости. Плечи и плечевые/предплечевые участки скрыты рукавами: жёсткость задаётся весами arm/elbow,
а не дополнительными видимыми костяными фрагментами. Пальцы в этой версии меняются вместе с кистью;
индивидуальные finger bones не нужны для четырёх подготовленных жестов.

Draw order в JSON, сзади вперёд:
`cape → left_sleeve → hood_back → face_neck → chest → right_sleeve → hood_front → eyes → cuffs → hands → deck → ribbons → marigold_leaves → marigold → eye_glows`.

Это адаптация предложенного Z-pass к существующим цельным панелям: плечи находятся внутри
рукавов, а head/jaw управляют одной сеткой face_neck. Отдельных PNG shoulders/head/jaw нет.
Цельный череп включает скрытый купол, а шея — ключицы под воротником. Поэтому face_neck
лежит под передним краем капюшона и жилетом: буквальное размещение всей сетки поверх них
показало бы скрытую анатомию через ткань. Ближний right_sleeve рисуется после chest, чтобы плечо заполняло пройму, а не выглядело
стоящим за пустым жилетом; дальний left_sleeve остаётся за корпусом. Передний капюшон
обрамляет лицо; обе кисти лежат
перед плащом, рукавами и корпусом. Ленты принадлежат бутоньерке, их pivots — у выхода из неё,
а не на нижнем крае плаща. Огонь глаз находится последним и не пересекает другие детали.

## Кости и координаты

**45 bones, 20 slots, 8 meshes, 882 mesh vertices.** Названия left/right означают экранную сторону:
left — дальняя рука слева; right — ближняя рука с колодой справа.

```text
root (0, 0; виртуальные стопы ниже waist-up рисунка)
├─ hips
│  ├─ spine_01
│  │  └─ spine_02
│  │     └─ chest
│  │        ├─ neck
│  │        │  └─ head
│  │        │     ├─ jaw
│  │        │     ├─ face_neck
│  │        │     ├─ left_eye → left_eye_glow
│  │        │     ├─ right_eye → right_eye_glow
│  │        │     └─ hood_front → hood_left / hood_right
│  │        ├─ hood_back
│  │        ├─ left_shoulder → left_arm → left_elbow → left_wrist → left_hand
│  │        │                    └─ left_sleeve
│  │        ├─ right_shoulder → right_arm → right_elbow → right_wrist → right_hand → deck
│  │        │                     └─ right_sleeve
│  │        └─ garland_01
│  │           ├─ marigold
│  │           └─ garland_02
│  │              ├─ marigold_leaves
│  │              ├─ ribbon_left → ribbon_left_tip
│  │              └─ garland_03 → ribbon_right → ribbon_right_tip
│  └─ cape → cape_left / cape_center / cape_right
├─ left_ik
└─ right_ik
```

Рабочая регистрация рисунка: 948×1659, масштаб экспорта `2720/1659`, защитная рамка мастера 40 px.
Виртуальные стопы в рабочей системе: **(474, 2600)**. Spine — Y вверх:
`worldX=(pixelX−474)×scale`, `worldY=(2600−pixelY)×scale`.
Поэтому root находится ниже PNG: waist-up не имеет нарисованных ног. Hips расположен у талии;
head — у основания черепа, jaw — у заднего сустава челюсти; плечи, локти и запястья привязаны к
анатомии под тканью. Все точные pivots и trim offsets — в `source/layer-registration.json`.
Для позиционирования кадра учитывайте видимые bounds, а не ожидайте root в нижнем пикселе PNG.

Обе двухкостные IK-цепочки имеют `mix: 0` в setup, чтобы сохранить художественную позу.
Для IK включить mix=1 и перемещать `left_ik`/`right_ik`. При направленном жесте компенсировать
поворот кисти на hand bone, если пальцы должны смотреть горизонтально.

## Четыре жеста

1. **Idle:** обе `_hand_idle`; колода выключена. Пальцы расслаблены.
2. **Holding a card:** `_hand_card` содержит одну нейтральную карту с целым захватом;
   используйте нужную руку, вторую оставьте idle, attachment deck выключите.
3. **Pointing:** `_hand_point`, указательный палец вытянут; локоть/плечо распрямляются через IK.
4. **Open:** `_hand_open`, полная ладонь и пять пальцев, жест вверх/вперёд.

Setup по умолчанию: дальняя `_idle`, ближняя `right_hand_deck` + отдельный deck. Опорная кисть
полностью дорисована под колодой, поэтому deck можно скрывать. Смены кистей повторяются в обоих
skins. Статические положения из preview служат проверкой и не сохраняются как анимации в JSON.

## Импорт в Spine 3.8.75

1. Сохраните JSON рядом с папкой `layers`, включая её подпапку `fs`.
2. Откройте Spine Professional → **Import Data** → выберите `character-a-setup.json`, scale=1.
3. Проверьте Images path: `./layers/`; регионов не должно быть Missing.
4. Сначала skin default и setup pose, затем skin fs; FS meshes связаны с default через linkedmesh.
5. Проверьте hand attachments и обе IK-цепочки; сохраните результат как собственный `.spine`.

JSON написан как импортный setup, не как экспорт редактора: поле `skeleton.spine` намеренно
отсутствует, версия экспорта не подделана. Это соответствует подходу официального
[Photoshop-to-Spine импортера](https://github.com/EsotericSoftware/spine-scripts/blob/master/photoshop/PhotoshopToSpine.jsx).
Формат, meshes и weights сверены с [JSON documentation](https://esotericsoftware.com/spine-json-format)
и [официальным runtime 3.8](https://github.com/EsotericSoftware/spine-runtimes/blob/3.8/spine-ts/core/src/SkeletonJson.ts).

**Импорт в самом редакторе 3.8.75 здесь не проверен:** установленного Spine Editor нет.
Отдельно: официальный runtime 3.8 отвергает именно экспорт с меткой **3.8.75**, что подтверждено
[Esoteric Software](https://esotericsoftware.com/forum/d/15704-problem-in-runtime).
Для будущего runtime-экспорта используйте исправленную версию 3.8 и соответствующий runtime;
не заменяйте номер версии вручную. Эта проблема экспорта не доказывает и не опровергает импорт
нашего authored JSON в ваш редактор — его нужно открыть там.

## P2-fix: применённые исправления

1. **Запястья и смены кистей.** Координаты right_wrist в исходном setup уже были едиными.
   Видимый сдвиг вызывал preview, который одновременно со сменой attachment передвигал IK.
   Эти действия разделены: контрол «Поза» меняет только изображения; «Поворот» отдельно
   проверяет суставы. Все кисти заново зарегистрированы по основанию ладони. Ошибка положения
   нарисованной точки запястья относительно кости — максимум **0,000105 px**;
   смещение самой кости между idle/card/point/open — **0 px** для обеих рук.
2. **Левый рукав:** 767×1319 → **767×1380**, +61 px снизу по требуемому конечному размеру.
   Дорисован внутренний заход манжеты. Отдельная rigid-накладка left_wrist заново извлечена
   из того же рисунка рукава, чтобы старый прямоугольный срез не проявлялся на новой панели.
3. **Капюшон:** 1411×1215 → **1411×1235**, +20 px снизу; непрерывная внутренняя ткань.
   Веса нижней части у шеи согласованы с head/neck. Верх и края остаются цельной панелью.
4. **Плащ:** 1281×1831 → **1281×1861**, +30 px сверху. Дорисован плечевой заход;
   верхние вершины связаны с chest и соответствующим shoulder. Прямые полосы ранней
   сборки убраны: экспорт использует цельные дорисованные панели, а не склеенные полосы.
5. **Кисти:** оба набора перерисованы в одном масштабе анатомии и стиле. Все 9 attachments,
   включая опорную кисть для колоды, имеют общий холст **330×400**. Это регистрационный
   холст с намеренной прозрачностью вокруг рисунка; он является исключением из tight trim.
   Палец pointing полностью сохранён: рисунок упакован вертикально, attachment повёрнут
   обратно на 90°. Кисти не растянуты отдельно по X/Y и не обрезаны для подгонки холста.
   FS-цвет кистей получен сопоставлением собственной BASE/FS палитры; их alpha совпадает.
6. **Бутоньерка:** вся garland-цепочка, цветок, листья и обе ленты сдвинуты **на 25 px влево**
   в масштабе мастера. Родительские локальные координаты пересчитаны; рисунок и кости
   двигаются вместе. Проверено пересечение PNG alpha кистей с листьями/цветком/лентами
   при каждом из 14 тестовых поворотов в обоих skins: **0 пикселей** при alpha ≥128,
   масштаб обзора 0,32. Это проверка экранного пересечения в этих позах, не любых движений.
7. **Pivots:** плечи в центре суставов под тканью, локти внутри сгиба, запястья у основания
   ладоней. Исходные анатомические pivots подтверждены и сохранены. Цветок — на нарисованном
   лацкане; ленты — под его основанием. Номера 1–9 на
   [мастере с crosshairs](qa/p2fix-master-pivots.png) соответствуют именам и точным
   world/masterPixel координатам в [setup-check.json](qa/setup-check.json).
8. **Слои:** руки вынесены перед одеждой, ленты/цветок — перед руками по требуемому Z-pass.
   Для цельного face_neck сохранены два необходимых перекрытия тканью, объяснённые выше.
9. **Посадка одежды:** после замечания Andrii пустой овальный воротник заменён открытым
   V с двумя бортами, прилегающими к реальной шее. Прозрачное отверстие показывает шею
   внутри одежды, а не переднюю полую трубу. Жилет перерисован в BASE и FS; голова остаётся
   отдельной цельной сеткой, и верх одежды не закрывает её соединение с телом.
   Ближний рукав вынесен перед краем проймы жилета; капюшон остаётся перед плечевым стыком.
   [До / после](qa/p2fix-neckline-comparison.png); исходный пример Andrii сохранён как
   `source/user-wearability-reference.png`. Предыдущая сборка — в
   `_archive/p2fix-before-neckline/`. Численный PASS сам по себе не оценивает посадку одежды.

Дорисовка выполнена встроенным **image_gen.imagegen**. Точные prompts, входные изображения
и пути сохранены в [p2fix-prompts.json](source/p2fix-prompts.json) и
[p2fix-fs-prompts.json](source/p2fix-fs-prompts.json), а исправление воротника — в
[p2fix-wearability-prompts.json](source/p2fix-wearability-prompts.json). Исходные изображения находятся в source;
экспорт только отделяет детали, масштабирует и регистрирует их. Предыдущий P2 сохранён целиком
в `_archive/p2-before-fix/`; промежуточные QA-кадры — в `_archive/p2fix-preliminary-proofs/`.

регистрация, QA-кадры, галерея и эта инструкция. Открыть галерею, сменить свет и кисти без
поворота, затем отдельно выбрать локти ±45°, плечи ±30° и включить pivots. Сравнить с мастером.
Далее на устройстве со Spine 3.8.75 выполнить Import Data и сохранить .spine — это открытая
проверка P3-0, исключённая пользователем из текущей задачи. Анимации и экспортный atlas — позже.
