# Этап 1 — арт-дирекшн Muerta Poker

Локальный просмотр: http://127.0.0.1:5190/phase3-art-direction/index.html

## Что сделано

Одна страница `index.html`: палитра из 10 цветов с hex/ролями, SVG-примеры состаренного золота/эмали/papel picado/бархата, видимые схемы света и толщин, Barrio + Oswald, инвентаризация прежнего арта и отдельный отчёт по каждому критерию «не ИИ-слоп».

Шесть полных ручных SVG-макетов в `mockups/`: desktop 1920×1080 и portrait 390×844, каждый в покое, с выигрышем и FS. Рядом шесть новых снимков текущей Pixi-игры того же размера (`screenshots/`). Карты не подставлены для красоты: взяты из существующего движка. Base — две руки Two Pair, 0.50 + 0.50 = 1.00; первый реальный JOB-спин — Jacks or Better 0.75 + Two Pair 1.50, банк ×3, 9 FS осталось. Прототип показывает финальные суммы, старые снимки захватывают работающий count-up. В каждом JSON сохранены cards и target_received от реального renderer payload.

HUD сохраняет действующую геометрию: desktop SPIN справа; portrait сохраняет существующий центр, бонус слева, счётчики в нижней полосе. Это разрешает требования «SPIN справа» и «раскладку менять нельзя» через текущие ориентационные варианты; мобильный HUD не переставлялся. Win/Balance/Bet используют Oswald. Turbo/Autospin в макетах используют ровно исходные пути `marks.tsx`; исходный компонент не менялся. Все новые тексты на странице — редакционные подписи отчёта; внутри игровых макетов только существующие формулировки. Языковые пакеты/social mode не изменялись.

Выигрыш обозначен золотой кромкой карточки и затемнением прочих карт; статический финал показывает обе руки. У Hand pays сохранены лампы, подсвечены только текущие выигрышные руки. Royal Flush в покое не имеет подсветки. FS получает бирюзовую эмаль рамки/банка и более холодный дальний план. Диагональной штриховки, blur/glow-фильтров, raster-images и шумовых паттернов в предложении нет.

Небольшие исследования туза, двора и отдельного Жнеца показаны на странице в 86×121 и 60×85, без увеличения. Это исследования масштаба и формы для арт-дирекшна, а не финальные новые карты. Дворы в макетах упрощены и не подменяют утверждённую Queen A: детальный ручной redraw всех 12 придворных после гейта ещё потребуется. Иллюстрации не собраны в новую колоду, production art/src и атласов пока нет.

## Как проверить

1. Откройте страницу по ссылке выше. Для шести сравнений выберите «Все шесть»; «Desktop» и «390×844» оставляют соответствующие три пары.
2. Нажмите «100% размер» у макета или текущей игры. Откроется исходный экран без уменьшения, с прокруткой. Escape закрывает просмотр.
3. В разделе «Материалы» разверните SVG-примеры: градиент, контур фаски и направленный блик; рядом есть полный исходник каждого материала.
4. В «Одна рука, один свет» изучите размеры 86×121 и 60×85. Особенно проверьте индексы, короны, глазницы и читаемость отдельного Жнеца.
5. Текущая игра: http://127.0.0.1:5186/?renderer=pixi ; portrait — тот же адрес в размере 390×844. Страница не меняет live-игру.

Для повторного построения макетов: `node reports/phase3-art-direction/build-direction.cjs`. Для повторной проверки защищённых файлов: `node reports/phase3-art-direction/check-protected.cjs`. Эти скрипты читают live-проект; пишут только в папку отчёта. Captures/visual QA используют установленный Node Playwright и Google Chrome: Python Playwright в локальном runtime отсутствует. Игра и отчёт обслуживаются только локально; ничего не опубликовано.

## Проверки

- `npx tsc --noEmit` — exit 0.
- `npm test` — 5 файлов, 39 тестов passed.
- `npm run build` — exit 0; обычное предупреждение Vite о JS chunk >500 kB остаётся, разбиение bundle не относится к этапу направления.
- SHA-256: совпадают все 37 математических файлов/книг/таблиц и 276 защищённых live-файлов. `hashes-before.json`, `hashes-after.json`.
- Визуальная страница: шесть пар, 12 изображений экрана, 10 цветов, четыре материала, переключатель и диалог работают; ширина страницы при viewport 390 равна 390. Браузерные ошибки и итоговые проверки геометрии — `review-verification.json`.
- Сохранены SVG и PNG всех шести полных макетов. PNG предназначены для просмотра, источник предложения — ручные SVG и воспроизводимый генератор. Текст в SVG не запечён в растры.
