# Spine rigs

| rig | project | animations |
|---|---|---|
| character | generated: `tools/make_character.sh` (no .spine) | idle_01, idle_02, spin_ack, small_win, cascade_continue, medium_win, big_win, anticipation, feature_trigger, feature_idle, settle_to_idle |
| symbols | `symbols/symbols.spine` | idle, win_pulse (+ variants), destroy_cloud (+ variants), column_beam, anticipation, halo_anticipation |
| chest | `chest/chest.spine` | idle, locked, unlock, unlocked, open, opened |
| frame | `frame/frame.spine` | idle, win (flash + shine sweep), anticipation, feature |
| screens | `screens/screens.spine` | back_big/mega/epic/max/intro/total (rays, glow, cloud band, coin and gem shower, sparks), back_burst, title_in/title_loop, hero_in/hero_loop (treasure chest), crest_in/crest_loop, banner_in/banner_loop, ribbon_in, clouds_sweep |

symbols come from V28; chest, frame and screens are generated by `tools/make_rigs.sh`
(regenerating overwrites hand edits in those projects). Those rigs are Spine 4.3 Essential (bones, slots, colour,
attachment swaps; no meshes/IK).

**character** now comes from the approved master frame (`character/master/master.png`, the bird `bird_*.png` on
its own canvas): `tools/make_master_rig.py` turns the whole painting into ONE weighted mesh (no cut pieces, so
nothing tears or shows missing underpainting), with bones for hips, chest, neck, head, eye lids, the raised
forearm and hand, halo, head wings, hair/sleeve/dress chains with physics and three cloud puffs. The bird sits
on the fingertip and flies with swapped wing frames. Landmarks are master pixels at the top of the script.
`make_character.sh` picks, first found: `character/master/` → `character/layers/` (`tools/make_heroine.py`,
the brief's layered set; the set in there now was rejected) → the V28 pieces below.

Older path — the V28 heroine is generated by `tools/make_character.py`, not exported from a project:
it uses weighted meshes and physics, which Spine Essential cannot open. The V28 painting (base + hair and cloth
pieces, placement in `character/src/v28_layout.json`) is flattened into `body_back` and `body_front`, both weighted
meshes on one skeleton (hips, spine, chest, neck, head, eyes, arms, hair/sleeve/cloth chains with physics), with the
halo and head wings between them. She blinks (lids squash), turns her head toward a glowing wisp with little wings
that rests in her open hand and flies around her head (the reference's companion bird). The painted arm cannot swing
far without tearing the sleeve, so arm angles are scaled down (`ARM_SCALE`); hops, head, halo and the wisp carry the
big reactions. The old V28 project is kept as `character/src/v28_character.spine` for reference.
QA: `?qa=character` (live, buttons per animation) and `?qa=character&sheet=idle_01&fps=3&n=12&cols=3&cell=128&from=0`
(frame sheet stepped at 60 Hz, for side-by-side checks with frames of the reference recording).
`symbols` has one skeleton per board cell; `symbol_slot` holds every symbol image and the game picks one
(H1 wand, H2 harp, H3 chalice, H4 scroll_feather, L1 heart, L2 purple_gem, L3 blue_gem, L4 green_gem, S halo_card).

Workflow: open a `.spine` in the Spine editor, edit, save, then from `frontend/`:

```bash
npm run spine
```

That exports JSON + a packed atlas into `frontend/public/spine/<rig>/`, which the game loads (and rebuilds the
generated character).
Game hooks: `src/spine/SpineCharacter.tsx` (reactions to spin/win/anticipation/feature/big win),
`src/spine/SpineBoard.tsx` (symbols: drop, win, burst, halo; frame: win flash, anticipation, feature glow; chests: unlock, open). `?nospine` falls back to the static art.
QA in the console: `SkyCharacterQA.names()`, `.play("big_win")`, `.now()`, `.log`.

`screens` uses the asset pack (titles, coins, gems, treasure chest, crest, plaque, ribbon, big clouds, rays):
full-size masters in `screens/src/`, packed at 60 % (`tools/export_screens.json`). Several Spine instances of the
one skeleton sit on DOM anchors (`.title-img`, `.bw-chest`, `.crest`, `.intro-banner`); numbers and texts stay DOM
(gold digit images). QA: `?screen=intro|super|epic|total|big|mega|epicwin|max|cloud` holds a screen in demo.
